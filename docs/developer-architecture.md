# 开发者架构

## 当前执行主干（2026-11 重写）

本节描述 Studio 当前的执行路径，下一节列出稳定版验收契约。重写前的设计另存于[历史架构](archive/architecture-before-stable-hardening.md)。
桌面入口 `create_studio_app` 在完整安装中还会加载 `project_watch.api.create_app`，再挂载 Studio 路由。整理旧代码时需分别核对这两个入口。

**一轮更新是三个任务**，由 `studio/spine.py` 分派，代码决定怎么查，AI 决定盯什么：

| 任务 | 模块 | 做什么 | 不做什么 |
|---|---|---|---|
| `collect` | `collect_job.py` | 冻结确认名、产品、监控方案与来源选择，按来源采集并入库。新闻可用 Bing News RSS 和已配置的搜索服务，符合条件的 Europe PMC 专利补读 Google Patents 原文页。模型可用时预筛本轮新闻并读取选中的正文，最后记录各来源健康状态 | 最终相关性审核位于分析阶段。单个来源的失败或未决状态记入该来源回执 |
| `analyze` | `analyze_job.py` | 相关性审核（含论文/专利与公司的关系）→ 事件归并 → 批次快照 → 分栏起草、证据复核、逐栏发布 → 问题评估、投资假设核对与预警、监控方案复盘 | 不采集；失败后对同一批次重做只发模型请求 |
| `report` | `report_job.py` | 记录本轮新事件。模型可用时排入简报和页面摘要任务，竞争与行业页需要刷新时排入环境分析任务 | 不采集、不分析 |

- **入口唯一**：“更新”、启用监控、新增关注点、新建项目和定时调度都调用
  `spine.request_round`；同一项目已有进行中的一轮时直接返回该轮，不另起一轮。
  新上传的内部资料分析完成后，`schedule_document_analysis` 只排一次不采集的分析。
- **派发规则唯一**（`dispatch.py`，`JobExecution.call` 对所有任务类型生效）：项目暂停
  （内部资料除外）或（公开轮次）未同意不发送；同一请求仍在途不发送第二次；同一任务内、
  或同一采集批次的各次分析里，此前结果不明或未标记可恢复的历史 5xx 请求不自动重发——只有所有者点
  “用已保存材料重新分析”（`redo:` 任务，页面先说明可能重复计费）才重发；之后的新一轮即使
  字节相同（无日期的搜索词）也是新请求，旧的不明回执保留、计入、永不补发；服务商退避。每个项目的请求和结果不明记录照常计入用量，不设应用次数或费用上限；
  旧额度配置只留作历史记录，不参与请求准入。其他任务的未决请求只记账，
  不阻断新的一轮。已完成的回答只在同一任务内回放。
- **快照属于采集批次**：同一批次的每次分析读同一份不可变材料，因此发出同样的起草请求，
  由派发规则决定能否重发。
- **投资假设与预警**（`assumptions.py`）：首次分析从公司资料起草 3–6 条假设，所有者可改、
  可加、可停止跟踪，改过的条目模型不再改写；每轮对照新信息给出得到支持 / 受到削弱 /
  无关 / 无法判断，只能引用本轮给出的条目，另列假设之外的变化，并提出至多 2 个
  探索查询词供下一轮采集使用。这些是信号，不是已确认的投资事实。
- **页面**：`GET /round` 给出收录、分析、完成三段状态；`POST /reanalyze` 需要
  `accept_duplicate_cost`；`/assumptions` 与 `/warning` 供“当前判断”页使用。
- **旧任务**：启动时 `dispatch.archive_legacy` 把未结束的 `external`、`external_followup`、
  `insight`、`scope`、`assessment` 任务标为 `archived`；它们的回执、产物和未决请求原样保留，
  不再续跑。DSH 执行器、跨任务恢复对话框和续接/准入模块已删除。
- **回放**：`replay.py` 把历史回执导入私有语料，`scripts/replay_collection.py` 在新数据目录
  里离线重放一次采集；语料和数据目录不进 Git。

## 稳定版收敛契约（待整体验收）

- 自动归并使用统一事件身份准入：标题相似只召回；每个组成员均需支持，模型引文不能只摘共用背景。显式手动归并仍保留版本检查与撤销。
- 近期新闻统计共用明确日期表达式，有当前时间上界，不用采集时间兜底。旧事件字段可能来自报道日；Agent 报道日仍作为新闻日期使用，不改写原事件字段。这不证明真实发生日已被独立核实。
- 分析固定同一材料快照和选材清单，方向交错、全文分片、批次检查点；每批大小在任务开始时冻结（`analyze_draft_batch_v1`）：新任务每批 80 段/64000 字，起草请求数约减半；已在进行的任务和沿用旧批次的同批重做仍为 40 段/32000 字，已存草稿照常重放；宽批次草稿曾因超出上下文窗口被截断时，同批重做退回原大小。批次大小只是请求大小边界，不是本轮额度。所有合格片段依次送入起草，最终仍须通过证据复核。处理过材料不等于每条断言均已正确提取。
- 旧协议先查反证再核对支持；新任务先逐栏核对引用支持，再对可发布候选查完整冻结材料的反证，并做跨栏一致性检查。请求边界按字段别名和引文锚点展开后的实际长度计算。每批结果持久保存；任何批次的有效反证均不能被先前支持覆盖。没有证据的批次不等于反证。历史未决分析不能借新复核请求格式绕过防重发。
- 反证范围在任务开始前冻结（`counter-scope-v1`）。尚未发送任何请求的新分析和摘要任务只查相关材料：断言引用的来源，再按区分度高的共同词（拉丁词、数字、汉字二元组）为每条断言各自选出最相关来源：最相关的一个不论长短都纳入，其余每条最多 8 个、约半个请求边界；多条断言合并核查时各自额度不变；与任何断言都没有共同词的来源不发送。已发送过请求的任务继续检查全部冻结材料。这一范围是成本取舍：与断言毫无共同用词的反证可能漏查，引用支持核验不受影响。
- 同一任务内互不依赖的复核请求最多 3 个同时发送，每个仍各自记账。第一个未完成的请求单独发送（接续时它可能是结果不明的请求）；出现失败或无效回答后不再发送新请求，已收到的回答照常保存，只在一批请求全部结束后才让出执行权。
- 旧分析检查点不能在升级后自动切换证据编号与请求协议；保留结果并明确中止，旧 unknown 不自动重发。
- 新建分析使用复核协议 v4：多来源综合不因需要归纳就视为仅部分支持，每项事实和必要前提仍须有引文；缺失年份、金额、排名和比较范围仍不能通过。摘要修订保留原栏目的复核来源，避免删去论点时丢失未变技术路线的依据。旧批次继承原协议，不能通过换提示词重发未决请求。
- HTTP 成功结束但正文为空属于已知输出失败，保留用量和原回执，不自动重发；单栏摘要修订失败不会阻止其他独立栏目的保存。
- wheel 必须逐文件对应当前冻结源码；Windows bundle 再核对安装字节。开发评测工具位于 scripts，不进入运行包。

历史实现参见 [归档](archive/architecture-before-stable-hardening.md)。发布状态以精确候选验收清单为准，本文不宣称已发布稳定版。


## 自动接续与逐页交付（2026-11-07）

- 暂时断网（仅明确 DNS / connect refused）、429、账户拒绝及新收到的 5xx 在同一任务内退避接续；每次尝试独立留回执，已完成响应复用。退避限制请求频率，不设研究次数或费用上限。
- 旧 unknown / started 与未授权恢复的历史 5xx 保留原样。超时、连接中断、重定向后的网络错误不判为未发送。自动恢复不保证服务端恰好计费一次；新 5xx 接续可能产生额外用量。
- 账户与权限错误每小时再尝试，限流遵守 Retry-After。暂停项目不发送。收尾步骤的可恢复故障不写成永久失败；已完成步骤检查点保留。
- 新摘要任务在批次间尝试发布各页的首个可用候选，核验仍检查完整冻结快照中的反证。后续批次继续提取新事实，最终再收敛候选；不逐批重复全库反证。失败不删除已有发布。旧任务沿用旧协议，不借升级改变请求绕过 unknown。
- 在相关反证范围下，摘要任务先为本轮各页待审候选做引用支持核验，再把各页新断言合并成一次反证核查；每条断言的结论按任务保存，早期与最终候选、不同页面中的相同句子不重复核查。合并请求未完成时，涉及的各页按原规则记为该页失败。
- 摘要按任务顺序保护发布头：旧任务不能覆盖新任务已发布的内容与依赖。自动失败与恢复状态在刷新后仍可读取。

## 等待、恢复与覆盖（2026-11-08）

- 模型连接建立有网络等待边界；连接建立后的响应不按固定研究时长中止。请求回执的空字符串 `deadline_at` 表示无处理期限，历史 `NULL` 保持原兼容语义。执行租约与续约仍防止并发写入。
- TCP keepalive 用于发现失联，不代表模型有进展。用户显式取消或执行权失效时可终止等待；打断在途请求仍记结果不明。普通桌面退出继续等待当前任务，只有显式 `drain?cancel_pending=true` 才取消在途连接。
- 完整收到的响应与用量先按租约落盘，再响应取消；后续接续复用完整回执。未知请求不重发，也不改提示词规避历史请求身份。
- 安全恢复不以第几次领取作为永久停止条件。相关性审核、事件整理和独立提取批次分别保留失败状态；无依赖的工作可继续，依赖未知结果的累计草稿仍保留在原断点。结构化资料批次不完整时不消费整个输入版本、不覆盖既有完整资料。
- 监控对象不再设总数、每方向数量或关联深度的存储配额；重复、循环、跨项目父节点、权限与版本检查保留。旧任务的模型请求措辞保持不变。
- 超长来源按原文句段拆分，引用保留来源身份与偏移。不可安全分割的超长断言保留为局部未完成，不截断后伪称核验通过。页面摘要与独立步骤失败统一映射为部分完成。

## 候选复用与来源约束

- 摘要候选复核缓存仅限同一任务、协议、模型绑定和冻结材料范围。候选全文、限定条件、引用或来源清单变化都重新核验；缓存不将 unknown、未完成或无效响应转换为成功。缓存读取、下一次发送和发布前重查全范围权限，包括未被正文引用的反证来源。
- 独立栏目的支持核验失败仅影响该栏；共享反证或一致性检查未完成时，所有依赖它的新候选都不得发布。持久响应保存后才可让出执行权，不取消在途请求；接续仍使用原任务和检查点。
- 当前有效的确认别名及来源中的明确简称可支持主体定位。具体且有来源的关联线索进入试关注，事实仍保留 pending；不自动恢复人工移除对象，不将方向或研究问题强制变成关系。
- 新闻涉及内部计划的影响句必须有当前、获准使用的内部引文。未获支持的影响句被移除，新闻摘要保留并记录原因。技术路线从原始标题、摘录或引用提取，不从模型生成的关系分类句造词；标题阶段线索保留否定、计划和主体限定。


## GLM 新请求传输（2026-11-08）

- 官方 GLM-5.3-flash 的新任务使用 SSE，逐行接收并记录首片段、末片段及传输字节数；收到结束原因与 `[DONE]` 后才生成完整响应回执，JSON 与证据核验沿用原逻辑。半途断流、缺失结束标志或错误事件保持 unknown，不自动重发，也不发布半截结果。思考片段不进入产品摘要。GLM 文档列出的结束原因 `sensitive`、`network_error`、`model_context_window_exceeded` 是明确的“无可用结果”，分别记为内容拒绝、未完成和超出上限的完整回执（可重放、不重发、可在独立步骤隔离），不是 unknown；文档外的结束原因仍为 unknown，诊断只记录该枚举词。
- 现有任务与同一采集批次沿用冻结的模型参数，不因升级改为流式而绕过旧请求身份。新流式协议不使用进程内协商缓存改变请求键；明确参数拒绝仍通过已保存回执确定性协商。
- 官方端点已确认的 GLM-5.3-flash 单次输出能力为 131072 tokens，与用户配置取较小值；仅用于新协议，不是任务次数、费用或研究时长配额。兼容网关和其他模型不套用该能力值。
- 私有诊断只保存阶段、耗时、字节数、允许的异常类别与系统错误码、取消原因及服务商请求号，不保存 URL、Key 或异常原文。当前路由标记只说明配置了代理，不宣称代理实际转发路径。流式不能保证避免上游首次响应前断连，unknown 仍需保留。


## 当前判断分批交付（2026-11-09）

- 新接入的判断任务冻结 `judgment-delivery-v1`。每批累计草稿先通过原有引用支持、完整冻结材料反证和跨栏一致性复核，再逐栏保存；后续材料继续起草，不等待全部起草完成才首次展示。
- 后续候选的复核包含此前已展示的栏目；同一候选及其对照版本固定检查点，接续不重新调用、不回退已发布头。失败候选不能清空旧结果，完整覆盖仍按全部材料遍历回执记录。
- 已进入旧复核流程的任务沿用原协议。有同批次未决请求时不通过换流程绕过；分批复核产生 unknown 后保留已发布栏目，不用后续候选重新发起它依赖的复核。未核验的草稿从不作为正式判断展示。

## 判断页独立核验（2026-11-10）

- 安全接入的新任务额外冻结 `independent_pages`。各页分别完成引用支持、完整快照反证及与已发布页的一致性后发布；不等待同级页面全部完成。
- 每页首次通过后，中间草稿仅继续整理；最后对累计候选做一次收敛，避免每个批次反复对已展示页面执行全量反证。
- 未决页面持久阻塞；其他页面继续。不同候选或最终收敛不能绕过该页的旧 unknown。发布对照版本在请求前冻结，中断后复用回执。
- 历史模式与已开始的共享核验不迁移；模型历史不可恢复 5xx 与 unknown/started 一样禁止借新请求格式绕过。此项修复不保证历史共享请求已经完成，也不替代真实分析验收。

## 公司本体判断停写（2026-11-11）

- 当前判断页以“公司进展”阅读替代“公司本体”判断后，新分析任务不再起草、复核或发布 `operations` 栏，也不把旧版本作为一致性复核的对照栏。范围在任务开始时冻结为 `analyze_section_scope_v1`。
- 升级前已开始的分析，以及同一采集批次已有沿用五栏的分析时，重做继续沿用原栏目清单：栏目清单不同就是不同请求，不能借此绕过历史 unknown。
- 已发布的旧 `operations` 版本保留，不删除、不改写；该栏在发布结果中标记为 `retired`，不计为“无新材料沿用”或失败。
- 公开页面摘要任务同样不再默认生成 `operations`（经营与资金）页：已保存页面清单或已发出请求的任务沿用原清单；显式指定的单页请求不受影响。
