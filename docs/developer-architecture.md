# 开发者架构

## 有据专业检索（evidence-query-v2）

未开始的首轮和增量采集角色冻结 `collection_retrieval_contract_v2`，启用
Europe PMC 与具体 Google Patents 文献工具；旧冻结输入和请求仍使用原 schema。
公开名称/产品线索带主体、关系候选及精确引文版本，不能据查询命中认定公司归属。
名称依据撤回、转为内部或被新版本替代后，不再授权新查询与语义准入。
产品补搜必须对应本项目本轮、同一披露支持的同主体机构查询；只有成功空结果或
原始署名尚未命中时才开放一个产品维度，仍受原来源/模型/分析预算约束。

具体专利记录按文献号读取一次第三方索引，保留原申请人、当前权利人、公开/申请/
优先权日期及字段 HTML 位置；不把 B 类文献号当作当前有效授权证明。
同族只合并展示，不删除版本；跨页显示已加载与已收录数量。
本批只有合成 HTML 与隔离普通入口验证，真实网页结构兼容性、真实召回和完整
研究效果仍须单独验证。详见 `plans/2026-10-30-evidenced-retrieval-design.md`。

## 渐进处理基础（隔离开发，首轮与持续监控默认入口已接入）

新建首轮 DSH bootstrap 在采集或模型派发前冻结 `material_pipeline_v1` 的 owner/policy。
已有调用、DSH 状态、旧采集准入或恢复记录的任务保留 legacy owner，不在恢复时更换请求身份。
新 monitor 的 refresh/incremental 同样走材料链；topic 和已经开始的旧 analysis-only 保留 legacy。
真实 Pipeline.run 在写通用 recovery_inputs 前冻结新 owner，恢复仍优先使用已有冻结入口。

新首轮先由现有宿主采集并持久化来源，经独立有界补读/采集阶段后，
再在父工具锁外执行独立材料角色；
只暴露 `pw_submit_records`，不再启动旧首轮 `pw_record` 模型循环。
候选必须显式提供分类、主体、标题、最多600字的陈述及稳定部件引用/连续字符位置，
宿主恢复原文后复用旧记录校验与语义准入；不按公司名、行业词或采集通道猜分类。
格式不合法或正常结束未提交的材料单独拒绝，其余材料继续；unknown、预算、租约错误仍停止派发。
有效候选汇总后统一执行既有字段及跨记录一致性复核，通过者先由原发布器持久化事件，
再整理档案和范围。后续档案收尾失败不清空已保存来源/事件；重启复用候选及模型回执。
事件投影按已准入候选分类，原来源保留 paper/trial/patent 等专业类别、条目 ID 和证据版本。
同一任务恢复时优先使用冻结入口，不因发布已推进 last_external_at 而切换为 monitor。
每份新材料开始前，按共享请求准入计数预留至多两次提取及当前实际语义复核成本；
不足时冻结本批并交付可复核的已完成部分。候选扩展使复核超额时，整份候选保留待承接，
不截断断言或标成已拒绝。延期清单引用原材料任务，原 owner 终止后可经现有 take_over
显式转交；未派发回执仅在宿主租约和 unknown/hold 保护下写入，不解除旧调用限制。
这不是逐条事件即时发布：材料阶段/复核未完成时仍只保留来源和候选，不冒充已准入事件。

显式模型总上限低于5次的新轮次不单独预留分析尾段：两次材料提取加实际准入复核
优先使用同一小额度，保存可负担的事件；分析仍需独立生成和复核，余量不足保留未完成。
总上限至少5次时保留原有最多6次/不超过一半的分析预留。默认额度、已冻结轮次和
更低的 executor 上限不变；同 job 恢复复用已完成投影和请求，不重新提取或复核。

普通 bootstrap/monitor 周期现在通过 `material_handoff` 自动检查可安全承接的延期材料，
无需单独调用 helper。采集前冻结该周期的实际请求上限；宿主及有界采集角色结束后、
材料提取前，检查同项目终态旧轮的 `publication_reserve` 清单、公开范围/配置、当前证据头、
人工排除、暂停及 unknown/hold。topic 不承接其他轮次。新周期先完成自己的来源检查，
旧轮耗尽不能把它的来源额度置零。

一个周期最多领取一个旧轮。任务 ID、证据版本、已结算提取候选、正文映射、来源引用、
原调用及继承账目在同一事务转交，并写唯一后继回执；事务失败全部回滚，重启复用同一归属。
全部请求种类的合并消耗不能超出原有限上限，模型至少须有三次保守余量，仍使用原提取/
复核准入规则。当前分析尾段总上限也取两轮较小值。journal 在写 started 前重新读取持久上限，
新的 executor 或分析 begin 不会使材料轮额度恢复默认；已收到的精确请求仍可零新增调用回放。

没有可证明的旧上限、额度不足、旧分析仍有独立责任、输入失效或派发对应关系不完整时，
保留原任务及具体原因，不转走后刷一份额度，也不自动建立无限后继。原额度耗尽的材料仍需
后续明确的额度准入方案；本接线不声称能清空所有历史积压。首次分析交接、未完成分析的
条件唤醒和跨整个验收旅程的有限总额度仍是独立未完成项。

`bootstrap_collection` 默认先有限补读，再以 fresh DSH 角色补充公开查询条件：
仅开放 search/read/collect/status/finish，最多4次模型请求、8个新外部动作、4次新页面读取。
finish 只结束采集，不发布记录或修改长期监控范围。专业查询复用 collection_targets 的精确公开引文校验，
缺范围、真实零结果、查询失败仍由原 ledger 区分。整个阶段共享父 JobExecution，预留材料提取及实际准入成本。
正文以不可变 parts 保存并保守标记 partial；只有确未派发的摘要任务才被显式替代。
原摘要、专业类别和条目不变；已开始输入保留旧版本。正文后段窗口和候选映射使用同一固定证据版本。
被冻结的采集输入及后续工具实际暴露的证据清单在每次模型派发前复查撤回状态，
不能把撤回材料继续传给模型；工具结果回放也保留这项检查。

采集角色派发前检查完整 JSON 请求体（UTF-8，包含消息和工具定义），上限32768字节。
已完成的精确请求先按原始字节匹配回执，不能因升级改写它的请求身份。
新的超限请求将较大的用户材料和工具结果替换为同 job 的可分页索引；
原消息和完整 JSON 以哈希校验的分块检查点保存，不删除正文、来源版本或匹配依据。
`pw_read(source_id="context:<sha256>", offset=..., view="record")` 仅读保存的索引，
每页至多4096字节，数组/对象按条目分页、字符串按 Unicode 字符给出精确窗口和 next_offset。
索引不是引文；原来源 ID、版本、正文引用及后续材料提取/语义准入规则保持不变。
每次读取及派发仍检查项目权限、撤回和 unknown。上下文无论如何压缩都容不下时，
明确结束该次有界采集，保存限制并交给既有材料处理，不裁掉 JSON 或重置模型预算。
采集角色的原生会话在已有完整运行回执时通过 SDK session/resume 恢复同一目录和身份，
再提交明确的继续提示；不新建任务/目录、不重发已有工具结果、不解除历史 hold。
它不自动批准过期验收或失败任务续跑，原请求与验收准入仍须满足。

明确未派发的 tool/args 可由宿主对已有 enqueue/claim 的新任务调用
`bootstrap_continuation.admit(execution, origin_job_id)`，随后由正常 run_external/外部 followup 入口消费。
它要求显式 owner/refresh 准入、终态原 owner、同项目公开来源及唯一后继；不自动排队。
旧完成动作读取保存结果，旧费用计入新轮冻结 cap，正文材料及来源映射随原任务显式转交。
新轮导入来源不冒充重新采集成功，也不重启原 discovery 模型循环；unknown/hold/lease/scope 仍保护两轮。
仅有“再次探索”意图属于另一个有界研究轮次；正文最多选用60000字，超限是不可续读的明确限制，
撤回来源 blocked、已冻结输入保留旧版，均不伪装为可自动执行的延期任务。
长文分段扩展与全量质量验证尚未完成，不能据此声明 P2 完成或上线。

### 自动归并的精确撤销

默认材料发布和旧事件聚类的 `attach_to_event` 在同一事务保存原成员、事件字段及前后不可变修订回执；
worker 调用在该事务重验租约与项目 unknown/hold。项目事件的 `GET events/{event_id}/merges`
列出回执，显式 `POST event-merges/{receipt_id}/undo` 撤销该次写入。
入口沿用 Studio 本地会话保护和项目边界；有运行中任务或 unknown/hold 时拒绝纠错。
只有实际字段、证据和成员仍匹配回执后的版本才恢复，不覆盖后来的人工编辑。
已读/收藏状态保留；新来源没有原事件时，拆回已准入内容的独立可见事件，不丢来源或不可变证据。
重复撤销只返回完成状态，不重复建事件。事件修订使相关 insight/question stale 并沿既有请求合并重建；
分析重建只跟随旧冻结修订的来源 ID 当前归属，包含拆回事件，不扩大到任意项目事件。
没有增加表或迁移；旧版本能保留新增回执，但不能用旧撤销实现解释 attachment 回执。
回退先停止并排空新版消费者，再保留数据库与回执；不得删除历史来恢复旧行为。

### 独立公开范围维护（P4 首个子批）

monitor 已准入关系记录在原 job 留下 `scope_maintenance_intent_v1`，事件和分析交接后由
现有队列排入独立 `scope` job。fresh 角色只有 context/scope/status/finish，没有综合判断、
搜索/读页、内部资料或永久订阅工具；最多4次生成。它选择已通过原材料语义准入的候选，
新关系只按 MonitoringPlan 规则加入公开 trial；已有范围修改形成待人工确认的 proposal。
临时问题仅从固定长期 parent 新建，继承其查询词、目标和别名，必须有退出标准，保留两跳、
总量与分区上限。安静关系不自动结束；新问题的材料与独立评估见下节。

关系适配固定公开主体/目标的唯一对象 ID、有效别名与整数版本；未建对象的技术/适应症等
保留项目内 typed target。稳定 link 含主体 ID、类型、目标身份、watch ID/版本及原 refs。
竞争关系可绑定既有 relationship scope_key/origin/version；其他关系不挤入竞争本体。
人工 exclude 决定由宿主检查，旧 link 指向关闭或改目标的范围也不能重新授权。
每次派发及提交事务检查范围、关系/人工决定、对象和公开证据版本；变动保留 pending。
新增/提案与完成回执同事务保存，提交后角色 checkpoint 中断可以零新增调用恢复。

事件触发的 scope 串接原 round budget tail，claim 等前驱终态，consumer 再继承前驱最终
own/inherited calls，避免队列提前建 child 漏掉前驱后来消费。scope 不成为本轮分析的前置条件。
既有公开范围首次轮询建立低频周期；27天到期是独立 cap=4 新轮，准入时持久化到期基准，
普通失败不会每次轮询重置额度。它复核已存范围与候选；广度来源仍由 baseline 的有界采集产生，
不自动增加一轮自由补搜。旧范围/证据失效、容量和未选候选保留明确原因。

没有新增 schema DDL；job/checkpoint/state 与原 plan history 继续承担持久化。
回退前须暂停 worker 并处理已排入的新 kind，保留回执和链接，不删除数据后用旧 worker 重放。
范围维护不代表无限扩张或上线；固定边界之外的候选仍明确延期。

### 独立问题评估与基础监听

新 topic 在真实 Pipeline.run 起点冻结材料 owner，复用有界公开采集、正文补读、材料提取和
事件准入，仅投影新闻，不修改公司档案或长期范围。旧已启动 topic 保留原 owner 和 wire。
新 monitor/topic 在来源完成后留下问题 outbox；现有队列的 assessment job 固定最多8个问题，
每题最多12个事件、48个精确公开引用及60000字引用输入。超界、无当前材料和未路由项保留原因。
角色只有 context/assess/status/finish，每题最多4次生成，不能搜索、改退出条件或调用综合
judge/revise。原独立语义 reviewer 复核答案、进展/资料补齐区别与固定退出条件；实际批次费用
不足就保存草稿。全部问题沿既有 round budget tail 共享原额度，不给每题或重建重置预算。

问题/父范围版本、探索 generation、全部待处理事件集合、事件修订、当前公开证据和模型/政策
在派发与提交时核对。提交事务追加 Questions 评估、消费精确事件、绑定依赖并保存完整答案回执。
人工已确认或中途改变结论的题目仅形成待确认建议；自动题目才可按原退出标准停止。失败、预算、
暂停和不完整来源/材料均不能关闭问题。知识状态 answered/unresolved/unknown/needs_recheck 与
job 运行状态独立展示。纠错/撤回保留旧答案全文和引用，合并重建；失败或过期输入不抹旧内容。
部分来源撤回时只冻结仍有效的公开引用；预期无效/超界重建保持 blocked_input_changed，不打断
基础来源排队。unknown、hold、lease 与项目暂停仍沿原执行保护处理。

基础来源 scheduler 不依赖专题是否休眠，也不依赖分析、范围维护或评估普通失败。新路由实质
内容沿既有内容 token 去重唤醒；已发布问题的依赖失效 generation 触发一次复核唤醒。重复
来源、旧回执与时钟更新不能反复唤醒。只有完整新查询集并完成材料/问题下游处理才调用原
Explorations.finish；含缓存的查询集明确记 reused，不能因缓存完成时间略晚于原计划时间多计
无增量。三个真实完整无增量轮次休眠问题，长期关系保持原状态。覆盖缺口和漏跑不补造成功时点。

此适配无新增 DDL；新 kind/checkpoint/state 和既有追加评估历史持久化。回退前暂停并排空或
保留 assessment 队列，不能交旧 worker 重跑新冻结输入。没有自由长文/图遍历、自动新预算轮、
全量实时质量或打包发布承诺；这些仍由后续质量和交付门禁处理。

### 事件交付与独立判断

新 monitor 复用上述有界采集、正文和材料准入，但采集角色不做 judge/revise，也不修改长期范围。
发布前在原 job 保存本轮已准入 URL/证据 intent，事件保存后以当前不可变事件修订构造分析输入。
终态 source job 的 intent 可由原 scheduler 重建；它只匹配该轮证据，不把任意后来事件算作该轮成果。
按已准入 claim.subject 与当前公开对象名称/有效别名的唯一匹配路由；歧义和输入限额留下明确待处理。
新冻结映射的 subject-v1 键保留同来源、同标题的不同主体；旧冻结材料映射身份保持不变。

每轮至多一个 insight job，内部串行分析最多8个对象，每对象最多20个事件、100个引用及60000字。
同一材料无需按对象再次提取。每个对象使用独立的 context/judge/status/finish 角色及既有 fresh 字段/一致性复核，
没有搜索、公开读页、采集或范围修订工具；上一判断只有 comparison 身份，不进入 numbered 事实来源。
分析成功无需 pw_revise。实际复核批次超出余额时保存完整 draft 和明确 pending，不将未审稿发布。
来源、事件、采集回执不因分析失败而删除或重跑。

根 round 冻结最多16次模型请求（显式更低额度仍有效）；先为采集设子上限，唯一 insight 继承原 calls/links。
各对象重建通过根 round 的唯一 budget tail 串接，包含前一对象重建的花费，不能重复花原有剩余额度。
source 终态前 insight 不可 claim；unknown/hold、暂停、lease 及配置/权限变化仍阻止派发。
现有手动“深度分析”入口明确准入一个新的有界分析轮，冻结当前可路由版本；它不是旧请求恢复或自动额度补充。
已经开始的旧分析保留请求身份，但不得通过旧 insight.save 覆盖已有 versioned head。

新增 studio_insight_versions 保存完整不可变判断、固定输入、精确证据、review/model binding、父版本和 job/round 来源；
studio_insight_heads 仅移动当前指针。发布在同事务检查当前事件快照、对象整数版本、有效关系及公开证据生命周期，
再写 DependencyStore/EventRevisions 依赖。关系专用证据也在依赖集合中；纠错使旧版 stale 可见并合并一次重建。
输入指纹同时固定模型与生成/复核策略；显式换模型会生成新版本，相同固定输入的已复核版本可本地复用。
旧版本全文保留，失败不清当前指针。UI 在原判断时间旁显示“依据已变化，保留旧版待更新”。

这是加表迁移，无业务数据回填/删除。重复打开幂等；回退代码须停止新 worker 并保留两张表及 immutable triggers，
不要删除历史或降级覆盖当前状态。已有 legacy 数据可继续读；新冻结任务应由匹配版本完成，不能混用旧执行器。
关系订阅/专题生命周期、低频范围维护、睡眠唤醒及集中打包发布尚未在本批完成。

`evidence_tasks` 将固定公开证据版本的候选提取与采集入库一起保存。
`material_ownership` 仅在原任务已终止、没有未解决调用或 hold 时，允许显式转交待处理材料；
沿用 JobExecution 租约、HTTP 与调用台账。已收到的相同请求复用原任务回执，不重复计用量；
旧调用仍计入承接任务的显式预算。旧适配器缺少材料与调用对应关系时拒绝自动承接。
这不是解除 unknown 或自动重跑入口。

单材料 DSH 提取器的候选、运行回执与至多两次不同请求准入分别持久化。
正常结束但未提交候选只拒绝该材料；网络、租约、预算与 hold 错误仍传播。
提取候选尚未通过语义复核，不能直接作为已确认事件或新闻发布。

`event_revisions` 为事件内容、来源内容及归属保存不可变快照；归并与撤销使用当前版本校验。
撤销仅恢复该次归并前的归属，不覆盖中途的证据更正；已读与收藏状态独立保留。
新增事件也推进分析输入版本，旧输入编译的简报不得覆盖新内容。旧事件首次补建版本也保守推进版本。
绑定事件的分析会在修订后失效并排队重建。兼容 Agent 来源仍使用不可变事件快照保留旧正文，
不是声称该来源已经由服务端抓取核验。一般拆分工作流、monitor 逐材料接线及完整分角色编排仍待完成。

ProjectWatch 是本机项目监控软件，输入公司名或材料，整理公开动态和内部资料，
以来源记录支持项目画像、竞争位置、技术路线、行业环境及投资问题分析。

## 当前发行候选的执行方式（2026-10-23）

- Windows 新安装包内置 Python、Node 和固定 DSH，公开研究默认由 DSH 执行；显式关闭设置或升级保留的旧执行器选择仍受尊重。运行时缺失或损坏显示“不可用”并阻断公开研究，不悄悄切换旧流程。设置变更在重启后生效。
- 源码运行不等同安装版：没有安装清单时保留显式环境配置；未配置 DSH 则使用原有执行方式。相关判断在 `studio/public_executor.py`，入口在 `studio/desktop.py`。

- 下面 DSH 两批迁移段落保留为历史边界，不能据其中“未捆绑”推断当前安装包。最终发布是否通过以 [发布准备状态](release-readiness.md) 为准，Mac 当前暂缓。历史实施计划和原始回执由维护者私下保存，不随净化源码导出。

### 关联主干与研究分支（2026-10-21 隔离候选）

公司资料 → 有出处的“因为／所以关注”关联 → 按频率采集目标变化 →
必要时建立临时问题 → 判断、修订、专题停止／新证据唤醒。
`scope_kind=relation` 是长期关联，目标和类型保存在 `relation_target/relation_type`；
`scope_kind=question` 是有父节点、退出条件的临时研究，继承父范围的目标约束。
空角色保留旧条目语义，不自动迁移。关系语义是否正确仍需审阅，引用校验不替代判断。

新 DSH 工具声明优先建立关联，不再引导首次补全生成独立的问题清单。
长期关联不进入无增益退出、不占逐问题评估清单；其事件仍进入综合判断。
研究分支停止或达到容量上限不关闭父关联。计划与 DSH 上下文附加分组 ID，
现有字段、人工结论和变更记录保留。前端改版和真实联网发现质量尚不在本次离线验收内。
详见 `docs/adr/0006-relation-first-monitoring.md` 和对应实施计划、验收记录。

政策价格对象另支持有限的原文关系匹配：从已存目标/显式别名提取对象前缀，
识别“对象医疗服务价格项目”或“对象相关服务纳入价格项目/医保支付范围”的明确结构。
此补充路径只读已保存的搜索摘录、部分/完整正文，不凭生成摘要拼接关系；保留
来源级别、连续原文及命中规则，研究问题仍要求局部关注条件。计划、否定和条件
只代表相关线索，不能当成已生效的政策结论。不新增行业泛词别名或改变生命周期。
这是有限语法，不是通用语义实体消歧；真实效果仍需按
[监控验收标准](monitoring-acceptance-criteria.md)复核。

Core、Contract、Insight、Legacy 是维护层级，不是完整开发者版的功能收费墙。
`scripts/layer_map.json` 与导入检查保留现有依赖约束；完整包包含全部现有分析实现。
兼容功能保留源码，不代表所有 team/PostgreSQL/外部执行器部署均已获生产验收。

## DSH 迁移历史：首轮公开档案（2026-10-20 隔离候选）

详见 [ADR-0005](adr/0005-dsh-public-bootstrap.md)。这是当时的 opt-in 候选记录，不代表当前安装包状态。

- DSH 负责“下一步搜什么、读什么、补什么”的模型/工具循环。ProjectWatch 保留
  任务租约、回执、证据、数据库、暂停与权限；这部分业务持久化不移交给模型。
- `PROJECT_WATCH_DSH_RUNTIME` 指向独立安装了 `@deepseek-ai/dsh@0.2.1-rc.2`
  的目录（其下有 `node_modules`），并要求 PATH 中存在 Node.js。
  不设置该变量时沿用当前流程。版本不匹配明确失败，不自动下载或回退。
- 仅迁移主体确认后的首次 `external` 补全任务；使用已配置的 OpenAI-compatible
  模型、公开搜索与阅读器。DSH 不等同 DeepSeek 搜索 API，也不要求改用 DeepSeek 模型。
  本批未适配 Anthropic 协议；其他路径不因此删除。
- DSH 只能调用五个公司/任务绑定工具。真实模型 Key 不传给子进程；模型请求经过
  本地鉴权网关及既有回执系统。禁止模型调用 shell、文件工具、任意 HTTP、
  商业接口及内部资料；这是能力约束，不是 OS 沙箱。
- 模型或付费搜索结果不明会锁定本轮，不换供应商绕过、不隐式重试。
  已完成的相同请求可复用回执。SDK 重试显式设为零。
- 首轮结束必须有结构化提交，不能拿 DSH idle/退出冒充成功。摘要、部分正文、
  完整正文分开记录；缺口保留为部分完成。

测试使用新目录、无后台 worker；真实验证脚本为 `scripts/dsh_bootstrap_probe.py`。
运行前应说明调用预算，必须显式传 `--live` 与用户已确认的主体，不接受复用非空
数据目录绕过历史请求锁定。运行产生的配置、DSH 会话和回执不得进入 Git。
以上为首批范围；持续探索、综合判断及修订的隔离扩展见下节。
桌面捆绑和断点会话恢复仍属后续迁移批次。

已另补隔离候选的“一次性授权续跑”：正式恢复接口发放的当前任务模型槽，
可启动从业务 checkpoint 继续的新 DSH 会话。旧 harness 日志和 unknown 回执保留；
新请求与授权槽、旧请求及新 payload 指纹关联记账。这是 checkpoint continuation，
不是旧 HTTP 请求逐字重放，也不证明旧请求未计费。只有收到有效新模型响应
才解除对应 hold；新的 unknown、其他任务/来源 unknown、配置变化继续阻断。
真实授权恢复仍按 [A09 验收要求](monitoring-acceptance-criteria.md)核查。

上下文传输使用可逆的前向引用：`numbered_same_as` 复用较早证据表，
`same_as` 复用条目，`context_same_as`/`excerpt_same_as` 复用完全相同摘录。
保留原始持久证据和消息协议，不回头改写已发送前缀。模型必须沿
`tool_call_id`/`ref` 读取原文；引用理解与实际缓存收益需要真实对照，
不能由字符压缩率代替。问题评估返回剩余清单和 `judge_ready`，
避免未评估完成就生成完整综合判断。

修订先整批检查字段及引用，校验错误返回可定位的 `issues`，业务执行结果按项保留。
收口说明从实际生命周期生成，模型说明只作附注；任务完成不等于所有专题停止。
相同公开输入、配置、提示及已存判断可凭严格凭证复用，analysis-only 任务直接续修订；
新证据或人工编辑使复用失效。发送前预算阻断与响应解析失败分开归因。
收口结果按 [A05–A08 验收要求](monitoring-acceptance-criteria.md)核查。

### 第二批历史：持续公开监控（2026-10-20 隔离候选）

在上述固定 runtime 基础上显式设置 `PROJECT_WATCH_DSH_MONITOR=1`：

- 首次公开档案完成后排入 DSH 补全任务；已有项目的 external 轮次由 DSH
  检索到期专题、读取、保存证据、提交综合判断、评估关注点、修订并结束。
- `pw_context` 只构造公开档案及公开事件来源，不调用内部/商业聚合器。
  判断复用既有报告期、披露状态、订单限定和置信度归一化。
- `pw_explore` 只能检索到期关注点的配置词；成功完成查询集才算一轮。
  明确回答、关联深度/容量边界、连续三轮无新线索可结束专题。
  新路由内容按指纹唤醒；旧内容重放和时间戳变化不构成新证据。
- DSH 无权解除暂停、改变配置或确认付费重试。未知请求锁跨任务生效。
  人工编辑的范围降频/改变只提交提案，旧版本输入不能覆盖新编辑。
  宿主声明的无鉴权公开读取超时/传输失败记为 `failed_read`，保留失败回执并
  继续其他来源；同请求不重发，分页已有结果按部分覆盖保存。付费调用、写操作、
  未分类请求及历史 unknown 仍保留保护。该策略仅用于宿主显式声明的无鉴权
  公开读取，不以 GET 方法或模型提供的网址推断权限；受限连接器包装的连接与
  TLS 失败同样隔离，TLS 校验和 URL/IP 限制不变。
- 判断和修订在同一外部轮次执行，不再额外使用旧自动 insight 指纹重复入队。
  该开关限定公开模式；其他显式处理功能及默认路径继续保留。
- 真实执行阶段映射到现有状态展示，不把 harness 的“选择下一步”冒充已经判断完成。

验证脚本 `scripts/dsh_monitor_probe.py` 只接受调用方明确准备的公开回执种子，
复制到新的空目录，不启动后台 worker、不自动重试。默认仅离线检查；
真实调用必须显式 `--live`，调用额度和缺失用量单独记录。
`--analysis-only` 只用已保存的公开证据，不开放搜索/阅读工具。
原始运行回执不随源码发行。这批历史实现当时未迁移内部/商业推理、未捆绑桌面
Node/DSH；当前候选的安装行为以本文开头和发布准备状态为准。

### 可选 DeepSeek Search

搜索网关新增 DeepSeek Search/Fetch；自动模式优先使用已启用的 DeepSeek，
博查、Tavily、Brave 与显式联合模式保留。DSH 与旧采集入口共用配置和搜索网关，
不额外挂载绕过回执的 harness 搜索插件。
模型与搜索同域名时按接口路径区分记账。未知付费结果不换源、不重试。
DSH 对搜索正文采用本地完整保存、按需分段读取；不将供应商摘要当作原文，
也不把搜索日期作为已核实的事件日期。配置与边界见
[DeepSeek Search](deepseek-search.md)。

### 专业来源与分析事件分开读取

临床、论文、专利栏目使用 `GET /api/studio/projects/{id}/research-sources`，
直接读取已保存的公开来源，不等待模型分级或事件发布。普通新闻仍使用事件接口。
来源 ID 不可用于事件状态、反馈或关联解释接口；栏目来源行仅展示原始来源信息。
项目详情的 `research_source_counts` 与来源接口使用同一可见性投影。

投影先检查人工排除、不相关、当前证据头的公开性与撤回状态，再计数、分页。
旧公开采集记录保留，新的 collection 记录必须有有效来源引用，不能回退旧快照
绕过撤回。接口仅输出限定的公开元数据，不输出模型摘要或任意原始记录字段。
来源发生变化时分页 revision 返回 409；前端最多重读一次完整已加载段，不混拼
不同版本。可见页面每 15 秒只读刷新，与分析完成时间无关；超过一页时图表标明
仅统计已显示来源，支持继续加载。检索命中、机构署名、申请人摘要均不自动证明
公司归属或专利权利，日期不明的收录不计入近期发表统计。

### 首轮、补充任务与待分析输入的衔接

新的 materials 首轮在事件发布前保存 `event_insight_round_v1`，发布后走与增量相同的
固定对象分析队列。首轮上限最多 40 次模型请求，分析预留在这个总额内，不是额外额度。
`external_followup` 通过 `collection_round` 绑定原根轮和前序任务，执行前导入前序最终
调用记录。模型、搜索、正文和公开接口沿用原轮累计限制；已有 legacy 任务仍走其旧协议。

已发布事件暂时无法对应明确对象时，轮次保存 `waiting_inputs` 和原事件集合，不以空对象
清单宣称分析完成。调度只读比较对象、事件、证据和关系版本；依赖变化后重新路由原事件，
不重做采集、不将后来无关事件纳入旧轮。相同输入已尝试但仍 pending 的判断保留待处理，
无变化的调度不重复派发；变更输入可在原轮剩余额度内排入新的固定分析任务。旧 unknown、
暂停、配置和证据有效性保护继续生效。预算不足保留原因，不补发新的额度。

材料承接与旧的未路由分析共用根轮：转交时在同一事务中绑定后继、收紧两边上限并更新
串行预算尾部，后续 scope/question/insight 均继承该根轮。已有分析任务占用尾部时仍保留
材料，不抢占它的责任。普通新周期先检查新来源；不能用新周期预算重置旧材料的余额。
此处证明的是任务衔接与保存语义；真实来源完整性、语义准确率、最新窗口和过期分析传播
仍须分别验收，不能以队列完成或离线合成测试代替。

发布意图不作为完成依据。整批事件与发布收尾写入后，单独保存完成标记、准确事件成员和
发布结果；意图后或部分事件写入后中断仍保持 collecting。同任务恢复复用已完成调用，
完成标记后的恢复复用发布结果，不再次改写事件导致已排队输入失效。补充任务沿用根轮
累计上限，但执行器已有更低限制仍取较小值；根轮标识/总额与单任务更低执行门槛分开保存。

## 有限公开验收批次（显式 opt-in）

`studio.acceptance_batch.create` 在既有 SQLite 中登记不可重置的批次：公开计划
SHA-256、绝对截止时间、最多两个原项目 ID、model/search/page/open_data/site 总额、
逐旅程静态额度以及有限根槽位。`bind_root` 只绑定同项目尚无调用的 queued/running
external 任务；必须在运行 Pipeline 前登记。它不复制项目、改变配置或自动运行研究。
公开实体姓名/官网与计划摘要被冻结；该摘要引用的公开样本、源码/安装身份、服务商和
单次上下文/输出限额仍须由验收执行者在开跑前核对。它不是自动构造整份验收计划的入口。

后继通过 enqueue 的显式 parent_job_id 在同一事务继承；事件分析、材料 followup、
公开 scope/assessment、旧 followup/brief 及新恢复任务已接线。相同任务恢复保留原归属；
不同项目或父任务冲突拒绝。未登记的周期/人工任务不能仅凭同项目身份加入批次，其新请求
会被拒绝；因此本能力仅用于明确安排的有限验收，不应附着到无人值守的日常项目。

JobExecution.call 在缓存命中之后、started 写入之前，在原 BEGIN IMMEDIATE 内检查
批次归属、公开实体、期限及额度。按 (origin_job_id, call_key) 去重累计成员和预算链接，
started/unknown/失败保守占额，不重复计算继承，缓存零新增。原更低阶段/执行器限额仍生效。
closeout 的 remaining 同时取共享剩余与原限额较小值。materials 路径每份材料最多
2 次提取并预留实际 publication review，既有分析尾段最多 6 次，均在原总额内；
只有 legacy 研究路径保留原 8 次收尾预留，不给 materials 叠加 8 次。
这是收尾建议，真正发送准入始终由同一写事务重新判定。请求数不是 token 或货币额度。

材料提取在发送前按实际 UTF-8 JSON 请求体检查 32KiB 边界，计入提示词、工具定义和
历史消息。超限仅延期本份材料：保存请求摘要、大小和原证据版本，完整原文不变，材料
仍为 pending，不写空提案或 rejected，不产生调用与未知结果。同一轮跳过已有延期项，
继续处理可容纳材料；全部剩余材料都被延期时明确以 material_context_limit 收尾。
完成的旧精确请求仍可复用，所有旧 unknown、来源及预算检查保留；延期不能用于跨任务
自动重发或重置余额。此机制不声称超限材料已阅读，也不以部分发布代替完整覆盖验收。

`close` 或到期只阻止新发送，不杀正在执行的传输，已完成回执可继续本地复用。unknown 的
已有暂停、同意和恢复约束不变。未 opt-in 项目保持原行为。批次不能重新开放、覆盖、重置
或转移项目，结束后继续保留审计记录。显式 `release` 只在关闭或到期、所有项目任务
排空且无请求/来源 unknown、未结算 5xx 或人工 hold 时，记录不可变结束凭证与任务边界。
之后新建的独立日常轮可以执行，项目暂停状态不变。原成员、原任务及其后继仍受原批
关闭/到期/额度约束；不能重新绑定、导入旧请求账本或承接旧材料绕过边界。重复结束不
刷新任务边界，不删除任何记录，也不允许同项目改 ID 再建批次重置额度。

队列复用须先匹配 kind/input_version，再校验已记录的父责任；已有未归属任务不能被
认领为批次后继。输入不匹配返回原任务供调用方等待，父责任不明/冲突拒绝，不写归属、
输入检查点或预算链接。

迁移仅增加四个 CREATE TABLE IF NOT EXISTS 表，旧请求/任务不重写，重开幂等。
本地验收库回滚须先停止其工作线程并保存完整库；旧代码不识别新门禁，不能降级后继续
运行已加入批次的项目。保留数据库/程序匹配备份，不删除账本来模拟重置。当前隔离验证
不代表原生 DSH、真实来源可用性或完整质量验收通过；真实验收仍须先冻结样本和执行边界。

## 专业公开来源与开放论文正文

OpenAlex 的分页和旧查询共用范围校验。机构名称中的逗号保留为搜索词；可引入额外
filter 的 `,field:`、布尔分隔符和控制字符在发送前拒绝。收到的 400/422、401/403、
429 和 5xx 分别记录查询、访问、限流和来源不可用错误；传输结果不明保留原分类，
不自动重试。单源失败仍由既有采集账本保存，其他已准入来源继续。

Europe PMC 提供机构/主题论文查询及生物医学专利索引查询。固定公开端点、字面短语、
分页游标、时间窗和既有调用预算共同约束请求，不引入凭据或新额度。结果先保存为
独立专业来源，保留原结构、稳定编号、DOI/PMCID、作者机构、许可和日期依据；搜索
匹配不代表公司作者身份、专利权属或已完成分析。专利索引保留供应方的 patentDetails，
但不提供完整专利覆盖、法律状态或同族核验。其 firstPublicationDate 可能来自申请日，
因此仅保留原值，不转换为新闻发布日期或近期事件。

仅已保存的 Europe PMC MED/PMC 开放获取标记和合法 PMCID 可进入固定 fullTextXML
正文端点。DSH 的现有 page 读取账本承接该请求，不调用付费正文服务。XML 必须匹配
论文编号并含许可及正文，禁止自定义实体；提取内容有长度上限并标记 partial_body。
不访问付费全文，不把截取正文称为完整全文。正文证据与元数据原记录分别保存，重复
读取复用既有证据，不重发已完成请求。来源列表可见不等于事件投影、分析或周报通过。

### 显式独立公开来源准入（默认关闭）

`public_source_once` 是本机受审协调器的有限入口，未接自动调度或 HTTP API。
它只使用原项目的既有终态 external 任务和调用账本；准备计划本身不联网、不写库。
计划固定公司公开名称/别名、配置和身份版本、人工来源选择、精确适配器 GET、旧调用及
恢复记录指纹。执行需另给计划哈希、明确同项目累计公开请求上限、新增上限和至多一小时
截止，并显式启用及传入运行时停止检查；默认不授予生产项目额度。

只允许 OpenAlex 机构、Europe PMC 机构及生物医学专利索引的首个有界页，每项至多20条，
一份计划最多4个明确查询。标准传输拒绝所有重定向，不重试；失败停止剩余查询。
旧模型 unknown 仅在精确冻结且不变时与这个公开读路径隔离，非模型未知或持久 hold 仍拒绝。
所有原有有限额度及验收准入仍生效；同项目全部历史公开请求保守计入新批准的累计上限。
永久 START/END 写在原任务，不能换任务 ID 重开窗口；进程中断无 END 时普通执行保持隔离，
需核查具体回执，不自动过期重发。正常任务也不能在这个独立读窗口里派发请求。
这个排他门禁只约束包含该实现的执行器；旧安装版不识别 START。实际启用前，受审宿主
必须确认所有同库工作线程已经正常排空并退出，或全部运行已验证包含门禁的版本，且
持有单实例排他权。不得在旧工作线程仍可能发送请求时单独启动协调器；运行时停止检查
也不能用空函数替代。当前实现未提供生产启动入口，不代表上述宿主条件已经验收。

回包后只通过原采集持久层保存来源并供 research-sources 查看，禁止材料任务、事件、模型、
分析和后继队列。已审核/已排除条目或撤回证据会拒绝本批写入，防止替换已有结论；先前
成功保存的来源保留。暂停、身份或范围变化后仍保存已收到的调用回执，但停止来源写入。
来源命中、零命中、分页未覆盖与语义相关性是不同结论；这条路径不完成公司分析验收。
