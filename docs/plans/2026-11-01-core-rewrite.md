# 核心重写：一条路径、账本记账、阶段落盘

2026-11-01。替代 2026-10-31 解耦方案中"在旧路径上加准入"的实现方式，保留其材料快照与分栏分析成果。
状态：方向已由用户确认（2026-11-01，见第 5 节），按第 7 节实施。分支 `claude/core-rewrite`，父提交为旧开发未提交改动的保存快照。

## 1. 为什么重写

近一个月的修复无法稳定走通，原因是结构性的，不在单个模块：

1. **结果不明被当成停机信号。** 同一条"项目内有未决请求"的判断分散在刷新入口、`material_ownership.project_guard`、每个 job 的 `dsh_hold`、business/details 跨任务守卫、验收批次等处，各自保守地全拦。修好一处，下一处继续拦。每次放行都要再写一个准入证明模块。
2. **长串行链共用一把锁。** 采集→读页→抽取→审核→事件→分析→今日→周报在同一个 job、同一个租约、同一个 hold 和预算下运行；任一环节失败整轮作废。成功率是各环节的连乘。
3. **确定性工作交给了模型。** 用确认名查论文、按公开号取专利，取决于 DSH 智能体在 4 轮、8 个动作内是否"想到"调用工具。同样输入、不同结果，难以测试。
4. **只增版本、不删旧路。** legacy/materials 两种 owner、continuation/successor/recovery 各自的准入、`_v1/_v2` 兼容分支同时存在；冻结的旧 job 必须走旧代码，所以每次修复都是"加一个分支"。
5. **真实反馈稀缺。** 合成夹具与真实提供方形状不一致（专利实页曾 3/3 失败而测试全绿）；真实运行需要一次性窗口和累计额度，失败即耗尽。

## 2. 五条规则

1. **账本只记账，不当闸门。** 每次外部调用有确定的请求键。结果不明（含已收到的 5xx）按全额计入已花费用，该键永不自动重发。除此之外不阻断任何工作。
2. **三个持久对象，阶段之间只通过它们交接。** 来源（采到即存、立即以"候选"可见）→ 材料快照（版本清单，不可变）→ 分析版本（按栏目发布）。今日动态与周报只读已发布结果。
3. **确定的事由代码做，模型只做判断。** 检索计划由代码从确认名、曾用名、产品、关注问题生成并直接执行。模型只负责：提议额外查询词（有公开原文依据才执行）、相关性审核、写分析。
4. **一个入口、一条路径。** "更新"= 创建采集任务；采集结束自动建快照；快照就绪自动排入分析；分析发布后报告投影刷新。没有 owner 判断，没有续接/承接特例。恢复 = 对同一输入重跑该阶段。
5. **真实世界便宜地进入开发。** 真实响应可录制回放；提供方格式用真实公开响应做契约测试；快速测试层作门禁。

## 3. 执行模型

### 3.1 请求账本与派发检查（替代所有 hold/守卫/准入证明）

沿用 `studio_job_calls` 与 `JobExecution.call`。新增唯一函数 `dispatch_check(project, kind)`，在发送前于同一事务内检查：

- 项目已启用且未暂停、已同意；
- 本周期预算剩余 ≥ 本次预留（未知与 5xx 已按全额计入）；
- 同一请求键已有记录：成功→本地回放；结果不明→不发送，返回"未知，未重发"；失败→按原有可重试分类处理。

不再存在"项目内其他任务有未决请求"这一类阻断。对同一请求键的重复发送由账本本身杜绝，所以不需要跨任务保护。

### 3.2 采集任务 `collect`

- 输入：项目确认名（含曾用名）、产品名、关注问题、来源选择；全部冻结在任务输入里。
- 计划由代码生成（复用 `collection_scope`、`collection_plan`、`CollectionSources` 适配器与解析器）。
- 每个结果到达即入库（复用 `collection_ingest`），在材料/候选页立即可见。
- 可选：一次结构化模型调用提议额外查询词，存为提议；只有能引用公开原文的提议才执行（沿用现有原文绑定校验）。
- 单个来源失败只记该来源的回执，不影响其他来源和后续阶段。
- 结束时写采集批次结果（complete / partial / failed），并自动排入快照与分析。

### 3.3 快照与分析任务 `analyze`

- 快照：复用 `material_snapshot`。对采集批次结束时的有效材料建不可变清单。
- 相关性审核：结构化模型调用，逐条给出"确认相关 / 候选 / 不相关"及依据，结果写入来源记录。不再作为入库前的闸门。
- 分栏分析：复用 `section_analysis` 的五栏与证据校验；各栏独立发布，一栏失败不影响其他栏。
- 事件：作为分析产物之一生成，不再是分析的前提。
- 重做：对同一快照再次排入 `analyze`。已成功的模型请求按键回放，0 次重复采集。

### 3.4 报告任务

今日动态与周报从已发布事件与栏目投影；不调用采集。历史论文/专利按其原始日期进入基线，不冒充当期新增。

### 3.5 模型调用方式

全部阶段改为直接结构化调用（`llm.LLM.json`，经同一账本）。不再使用 DSH 智能体子进程、本地网关、SSE 回放与会话续跑。

## 4. 旧数据与旧任务

- **数据全部保留**：来源、证据版本、历史分析、事件、累计费用、全部请求回执（含 unknown）。
- **旧任务一次性归档**：所有未结束的旧 job 标记为 `archived`（新终态，附原因）。它们已产出的来源与证据作为普通材料被新快照读取。它们的 unknown 请求保留在账本中，按已花费用计入，永不重发。
- **不提供旧协议的续跑代码**。归档后旧准入、owner、续接、handoff 代码全部删除。
- 迁移为增量且可回滚：只新增状态值与新表；不修改已有请求行。

## 5. 已确认的决定（2026-11-01）

1. **里程碑只认两条用户结果。** (a) 已有项目点一次"更新"，相关论文/专利出现在页面并可追溯原文；(b) 新建项目完整走到分析、今日动态、周报。其余验收项（干净 Windows、休眠离线、临床监管来源、48 小时观察等）放下一阶段。
2. **重写主干，先替换、后删除。** 新主干在隔离环境完整跑通 → 切换入口 → 删除旧代码。录制—回放作为第一步。
3. **流水线，去掉 DSH。** 代码决定查什么；模型只提议查询词、判断相关性、写分析。开放式深度探索以后作为独立的"专题研究"功能，不在每日更新主干上。使用 DSH 的跟踪问题评估与范围维护在 v1 中暂停自动运行，已有结果照常显示，之后改为直接调用。
4. **开发轻、里程碑重。** 开发期只用隔离环境、录制的真实响应和快速测试层作门禁；里程碑时做一次完整审查与真实验收。真实验收使用单独的小额预算（额度届时由用户确定），与用户实例的费用保护分开。保护规则不变：不重发结果不明的请求、不超支、不改历史。
5. **未决请求改为记账**（第 2 节规则 1），替代"项目内有未决请求即阻断"。

## 7. 实施阶段

| 阶段 | 内容 | 完成标准 |
