# 判断页语义与呈现（2026-11-10）

承接 [判断页流程隔离](2026-11-10-judgment-flow-isolation.md)。那份方案解决了"一页失败拖住别页"，
本文处理剩下的一半：**为什么页面上那句"无法判断"分不清是谁说的，为什么已核验的内容仍然不显示。**

范围限定：只改状态语义与呈现契约。不放宽核验、不改提示词、不改评级档位、不新增模型调用。
文中示例均为合成数据。

## 一、现状：五种不同的事，长着同一张脸

| # | 实际发生的事 | 代码位置 | 页面表现 |
|---|---|---|---|
| 1 | 模型自己判 `unclear`（材料不足） | 模型输出 | 无法判断 |
| 2 | 摘要句命中限定词规则，`verdict` 被改成 `unclear` | `insight_generation.py:652-654` → `:695-703` | 无法判断 + 空摘要 |
| 3 | 摘要句被就地改写（"尚未确认收入" → "收入确认情况待核实"） | `insight_generation.py:325, :366` | 看不出被改过 |
| 4 | 整栏 `rejected`，摘要清空 | `insight_generation.py:704-705` | 无法判断 + 空摘要 |
| 5 | 共享反证返回空，所有依赖栏一起 `blocked` | `section_analysis.py:265-268` | 整栏消失 |
| 6 | 该栏从未有可发布版本，投影用空模板填充 | `section_analysis.py:423, 459, 494` | 五栏全空 |

这六条在界面上同形，因为两处判据把它们压成了一种：

- `frontend/src/questionAnalysis.tsx:41` `judged()` 只认"摘要非空"，空摘要等于没有判断。
- `frontend/src/judgment.tsx:67-71` `Scale` 在 `unclear` 时留空轨道，`judgment.tsx:74` 提示为"尚无当前判断"。

更靠下的原因在词表：`src/project_watch/studio/insight.py:13-19` 把 `unclear` 定义为六个档位之一，
显示名就是"无法判断"。也就是说，"没有判断"被建模成了"一种判断值"。档位只能表达程度，
无法携带原因，所以无论模型看不清、程序降级还是系统没跑到，落到这个字段上都只剩同一句话。

于是三种性质完全不同的事，用户读起来完全一样。这是当前最需要修的一处：它让可信的内容和
不可用的内容无法区分，用户只能整体不信。

## 二、三条原则

1. **判定权归位。** 模型负责判断，程序负责把关。程序可以拒绝采用某段文本，不得替模型写结论。
   凡程序改写过的地方，必须留下 `verdict_source` 与 `reason_codes`。
2. **辅助检查没有否决权。** 跨页一致性、共享反证属于提示级，只给页面打标记，不阻断单页发布。
   单页能否发布，只由该页自身的引用支持与反证决定。
3. **展示单调。** 已经核验通过的版本，不因新一轮失败而消失。失败只影响"能否换成新版"。

## 三、四层职责

| 层 | 允许 | 禁止 |
|---|---|---|
| 产出 produce | 取模型输出、记录请求键与 token | 任何归一化、纠错、补全 |
| 核验 verify | 逐条断言给出 `pass`/`fail`/`unverified` | 修改或清空被核验的内容 |
| 裁定 decide | 保留、标注、隐藏单条、整栏置为未定 | 生成句子充当模型结论 |
| 交付 deliver | 换 `head` 指向新版本 | 用空模板覆盖已有版本 |

当前 `normalize()` 把产出与裁定合在一处，所以"整理格式"的过程中顺手改掉了结论。拆开的收益是
裁定变成纯函数：同样的输入与核验结果必然得到同样的页面，可以离线重放、可以单测、可以回答
"这页为什么不显示"。

## 四、页面信息结构

判断页的主体是**五栏证据**，结论是每栏的一枚标签。页面上不设总判断横幅。

每栏固定八个元素：

| 元素 | 说明 | 空值处理 |
|---|---|---|
| 栏名 | 竞争位置、技术、行业、运营、产业链 | — |
| 倾向 | 五档标签 + 置信度 | 显示"未定" |
| 摘要 | 模型原话，不裁剪语义 | 显示该栏状态原因 |
| 待确认 | `change_if`，最多 4 条 | 省略该行 |
| 依据计数 | 支持 N · 反对 M | 显示 0 也要写 |
| 核验状态 | 已核对原文 / 未核对 / 未通过 | — |
| 版本时间 | 该栏版本的生成时间 | — |
| 状态原因 | 出现 4、5、6 类情况时的一句话原因 | — |

`change_if` 字段在 `insight_generation.py:684` 已经产出并入库，目前前端未使用。它比结论更有
行动价值：告诉读者下一步该问什么。

## 五、五种页面状态

| 状态 | 判定条件 | 界面含义 |
|---|---|---|
| `judged` | 有倾向且摘要全部通过核验 | 判断可用 |
| `judged_annotated` | 有倾向，摘要中部分断言未通过核验 | 判断可用，某句存疑（就地标注） |
| `undetermined` | 模型判 `unclear`，或该页无有效依据 | 无结论，附原因 |
| `stale` | 本轮未产生新版本，存在历史版本 | 显示旧版，标注"本轮未更新" |
| `absent` | 从未有任何版本 | 尚无内容，附材料到达状态 |

判定顺序自上而下，命中即止。`stale` 与 `absent` 的区分是重点：前者有内容可看，后者没有。

## 六、降级规则

程序对一栏只能做四个动作，且每个动作都要带原因码：

| 动作 | 效果 | 原因码示例 |
|---|---|---|
| `keep` | 原样发布 | — |
| `annotate` | 保留句子，标出存疑片段 | `unscoped_superlative`、`recognition_unverified` |
| `hide_item` | 隐藏单条依据，其余照发 | `point_without_support` |
| `undetermined` | 整栏置为未定 | `no_supported_items` |

禁止再做第五种：**替换句子**。`_uncertain_summary()`（`insight_generation.py:454`）当前拼装的
"收入确认情况待核实；暂无法形成整体判断"这类句子，本质是系统状态文案，不能出现在摘要位置。

若某栏必须置为 `undetermined`，原始输出仍要保留，界面提供"查看模型原始输出"入口。用户有权
知道模型原本说了什么，以及为什么没被采用。

## 七、文案

| 状态 | 不再使用 | 主文案 | 副文案 |
|---|---|---|---|
| 模型判不清 | 无法判断 | 未定 | 缺 2 类材料：随访数据、注册进度 |
| 程序降级 | 无法判断 | 未定 | 依据未通过核验，已保留原始输出 |
| 历史版本 | 无法判断 | 显示 11-03 版本 | 本轮该栏未通过，可单独重跑 |
| 从未有内容 | 无法判断 | 尚无内容 | 材料未到达，预计下次采集处理 |
| 部分存疑 | —(原为无法判断) | 倾向照常显示 | 「全球首款」缺比较范围，未通过核验 |

"无法判断"四个字从界面上移除：它在原文里从来不是判断，只是占位符。

配套改动：`insight.py:13-19` 的档位词表把 `unclear` 的显示名改为"未定"，并把"为何未定"移到
`reason_codes`。`unclear` 是否继续作为档位存在，取决于是否允许模型直接输出"未定"；
建议保留该档位表示模型主动弃权，另用状态表达程序降级与系统未运行。

## 八、数据契约

在现有 `studio_insight_versions.record` 上扩展，不新建表：

```
analysis[section] = {
  verdict, maturity, consensus,        # 展示值
  verdict_source,                      # model | policy | unavailable
  reason_codes: [string],              # 降级/失败原因
  summary,                             # 模型原话（annotate 时保留原文）
  annotations: [{span, code, note}],   # 就地标注
  evidence_counts: {support, oppose, checked, unchecked},
  published_at,
  checks: [{unit, status, code}]
}
```

幂等键：`page_key = (project_id, page, input_revision, policy_version)`。重跑命中同键直接复用
既有裁定，不重发模型请求。这让"未知请求不敢重试"变为可计算成本的重试。

`head` 单调：新版本只有在状态等级不低于现版本时才切换，等级为
`absent < undetermined < stale < judged_annotated < judged`。同级时取较新者。

## 九、验收（离线，无真实调用）

1. 重放现存记录：只有被程序改写过的那一栏 `display_verdict` 与 `raw` 不同，其余全部一致。
2. 合成输入：摘要含无限定词的"全球领先" → 状态 `judged_annotated`，倾向保持模型原值。
3. 合成输入：共享反证返回空 → 其他栏仍 `published`，仅该栏标记 `shared_check_missing`。
4. 合成输入：本轮全部失败 → `head` 不变，状态 `stale`，旧内容仍可读。
5. 前端：五种状态各自渲染不同文案与 `aria-label`，键盘可达。

## 十、明确不做

- 不放宽任何核验条件，不为了让页面有内容而放行未核验文本。
- 不改提示词、模型配置、评级档位定义。
- 不引入新的存储表或新的分析平台。
- 不针对具体公司或行业补规则。
- 本轮不调用付费服务，不重试历史 unknown 请求。

## 迁移顺序

1. 加 `verdict_source`、`reason_codes`、`evidence_counts` 与五态，不动判定逻辑（纯增量）。
2. 把 `normalize()` 的改写搬进纯函数 `decide()`，`raw` 保真入库。
3. 共享核验从门禁降为标记（触及 `section_analysis.py:265-268` 与
   `tests/test_studio_insight_consistency.py` 的既有语义，需维护者确认）。
4. `head` 单调 + 幂等键。

第 1 步风险接近零，且能立刻把三类"无法判断"区分开；第 3 步会改变现有测试基线，单独评审。
