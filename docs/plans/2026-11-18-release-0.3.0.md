# 0.3.0 发布计划（2026-11-18 起）

目标：把 0.3.0a3 新流水线推进到 **0.3.0 Windows x64 公开测试版（beta，GitHub prerelease）**，再视反馈转稳定版。
门槛沿用[发布检查表](../release-checklist.md)和[真实监控验收标准](../monitoring-acceptance-criteria.md)；
本计划只排顺序、负责人和退出标准，不把任何门槛改记为通过。日期是目标，不授权绕过未完成项。

## 当前状态（隔离测试实例，2026-11-15 至 11-18）

| 指标 | 现状 | beta 退出标准 |
| --- | --- | --- |
| 分析轮次 | 12 轮完成，平均 106 分钟 | 增量轮次 ≤ 60 分钟 |
| 栏目发布 | 每轮 3–4/4 | ≥ 80% 的轮次 4/4 |
| 页面摘要发布 | 最近一次 5/11（2 页经开头重写），格式失败 2 页 | 每次 ≥ 9/11，格式失败 0 |
| 任务因内部错误失败 | 4 个（采集、竞品、业务详情、页面摘要各 1，`OperationalError`） | 0 |
| 竞品任务中途输入变化 | 2 次 | 0，或查明为正常并自愈 |
| 结果不明请求 | 45 个，均未自动重发；1 个因服务意外停止导致任务失败 | 只来自服务商传输，且不造成整任务失败 |

| 离线回归 / CI | 5094 通过，13 跳过；CI 全绿（PR #34） | 冻结候选上全绿 |

## 阻断与问题清单

| 级别 | 问题 | 现状 | 计划 |
| --- | --- | --- | --- |
| P1 | 数据库锁（`OperationalError`）使任务整体失败，跨 4 类任务 | 未查 | M0 首项：定位锁的持有者与超时，改为可重试或隔离，补回归 |
| P1 | 整体页面摘要发布率不稳定（1–8/11） | 已修多项；失败原因现已记录 | 跑 2 轮看原因分布；必要时要点附原文短引用，减少拼接与推断 |
| P2 | 竞品任务运行中输入变化导致失败 | 2 次，原因未明 | 查明改动输入的写入方 |
| P2 | 连接阶段 `OSError 10048`（端口耗尽）被记为结果不明 | 已定位分类问题 | 连接前失败记为未发送；采集并发连接复用或限流 |
| P2 | 服务意外停止时在途请求使整个页面摘要失败 | 设计如此（不重发） | 评估在途请求在启动时的处理，或只隔离该页 |
| P3 | 新材料筛选被服务商掐断较频繁 | 已逐批隔离，只记录 | 观察频率；考虑下一轮补筛 |

## 维护者决定（2026-11-18）

- 已批准：0.3.0b1，Windows x64 公开 prerelease，Mac 继续暂缓；目标发布日 11-25。
- M2 及我方其他测试的用量不设上限；结果不明仍立即停止，不自动重发。
- M3 在维护者家中另一台 Windows 电脑进行，由维护者本人按干净电脑验收步骤操作；Claude 在旁待命，只在被要求时协助，并记录每个求助点。需准备可独立使用的交接包（安装器、校验清单、按 0.3.0b1 更新的验收步骤、给该电脑上 Claude 的说明）。

## 节奏

每天一次进度汇报：完成项、指标变化、阻断、次日安排。测试实例的监控只作为安全兜底，不再作为主要工作。
