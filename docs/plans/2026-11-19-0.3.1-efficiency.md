# 0.3.1 计划：分析轮次的时间效率

状态：维护者 2026-11-19 同意列入 0.3.1。0.3.0b1 冻结后不合入。

## 依据（科大讯飞增量轮，2026-11-19，测试实例）

| 任务 | 模型请求 | 输入 token | 说明 |
| --- | --- | --- | --- |
| 细节提取 details | 187 | 197 万 | 两次运行各 42、46 分钟 |
| 页面摘要 page_summary | 173 | 334 万 | 输入多于章节分析，存在同批材料跨章节重复发送 |
| 章节分析 analyze | 119 | 319 万 | 1 小时 21 分，逐条串行，平均约 40 秒/条 |
| 业务画像 business | 57 | 100 万 | |

另有约 420 次搜索、网页与公开数据库请求；这类请求各自不同，无法合并。
整轮含后续任务约 3.5 小时。

## 不改变的原则

- 分批提取：单次上下文有限，长输入降低引用准确度。
- 核查与生成分开：每条结论对照自身来源单独核查。
- 结果不明不自动重发；小批次使一次失败只影响一批。

## 计划项

1. **同项目内互不依赖的模型请求并发**（目标 3–4 路，受服务商限流约束，可配置）。
   结果不明、暂停、租约与费用上限语义逐条保持；先在隔离实例测并发下的锁与限流。
   预期：章节分析与细节提取墙钟时间约降至 1/3。
2. **页面摘要减少重复发送**：按章节先筛选相关材料，或复用已提取的结构化结果，
   不再把同批原文发给多个章节。以输入 token 和发布率前后对比验收。
3. **小章节核查合并**：结论条目很少的章节，核查请求合并为一次；
   核查仍独立于生成。
4. **后续任务排队**：细节、业务、竞争等互不依赖的后续任务评估并行运行，
   先解决长写事务（12–21 秒）对其他任务的阻塞。

## 验收

同一测试项目、同一材料快照前后对比：整轮墙钟时间、模型请求数与输入 token、
各章节发布率与核查标记数量；不得出现结果不明增加或重复计费。
