# 用自己的 Agent 修复 ProjectWatch

适用于 Codex、WorkBuddy 或其他能阅读代码的工具。用户自定义代码与公共版本分开管理；本指南不授予额外第三方权利，也不要求把私有数据交给社区。

## 一次修一个可复现的问题

1. 读根目录 AGENTS.md、[架构](developer-architecture.md)、[开发指南](contributing.md)和对应版本限制。记录提交、系统、运行模式，不先更新所有依赖。
2. 保留现有本地改动，在独立分支或工作副本创建专用虚拟环境、空数据目录和空闲端口。不要复用产品数据库、其他人的 editable 环境或现用端口。
3. 从公开信息或合成材料建立最小复现。没有用户明确同意，不读取其真实 BP/配置，不调用模型、搜索或商业数据源，不做费用重试。
4. 写能暴露问题的测试，确认修改前失败，再做最小修复。针对措辞或行业的分析错误先记录为评测样本，不自动新增关键词黑名单、正则或提示词禁令。程序检查应表达通用的不变量。
5. 运行相关测试及相邻回归，报告通过、失败、跳过和未覆盖。数据迁移/安装/执行器修改需要对应生命周期验证，不能用单测替代。
6. 检查 diff、第三方来源和敏感内容，再由用户决定是否提交 PR。禁止强制覆盖本地定制、全盘回退、删除失败测试或吞掉异常。

结果不明的付费请求不自动重试、不删除回执、不换任务绕过。程序是否运行、任务是否结束、内容是否准确分别验证；“HTTP 成功”不等于判断成立。

## PR 最小交付

- 问题、影响版本、公开或合成复现；分析问题附可公开的依据与保留限定。
- 改动范围、前后测试命令和结果，失败/跳过/环境限制如实列出。
- 数据/配置兼容性、是否需要迁移或重打安装包；不得在用户活动数据库上演练。
- 依赖及许可变化；按[贡献授权说明](contributor-authorization.md)确认有权贡献。AI 生成不代表自动拥有所引用代码的发行权。

维护者复核后才合并和发行。Agent 可以提修复建议，不能自行标记事实已确认或代替用户批准收费、发布与数据操作。

## 可直接交给 Agent 的任务描述

> 先读 AGENTS.md 与 docs/agent-contributing.md。针对我提供的问题，在独立目录用公开或合成数据复现，先写失败测试，再做最小修复并跑相关回归。保留全部本地定制，不碰现用数据、配置与任务，不发起付费请求，不重试结果不明的请求。不要扩功能，不针对单一措辞补规则。最后给出 diff、测试通过/失败/跳过/未覆盖、兼容风险及 PR 建议，提交、推送与发布按我的明确授权执行。

日志和截图必须自行脱敏；[SUPPORT](../SUPPORT.md)说明哪些内容不能公开。无法脱敏时只报告问题类别，不为凑复现上传真实材料。
