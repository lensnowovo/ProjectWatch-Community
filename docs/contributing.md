# 参与开发

先阅读开发者安装指南、架构与已知边界。使用自己的独立环境和合成数据，
不在任何用户的真实实例上进行自动测试。

修改前明确问题、预期行为和回归用例。保留解析、存储、监控与已有分析能力，
不通过删掉失败测试、关闭分析或吞掉错误取得通过结果。
涉及持久化时保留迁移并执行升级/备份恢复演练；涉及外部调用时保留用量和未知结果保护。

提交前运行对应 Python、Node 和前端类型检查；安装相关修改验证新环境 wheel 安装。
在说明里分别列通过、失败、跳过和未覆盖，不能用配置存在代替真实执行证据。
不要提交 Key、真实材料、运行数据库、日志、备份、机器私有路径或生成的依赖目录。
任何新增依赖、字体、图像或改编代码必须记录来源和许可。

## 本地完整回归环境

先新建并激活专用虚拟环境，不复用其他开发者的 editable 环境。完整测试包含团队、MCP、OCR 和桌面路径，仅安装基础包或 `[dev]` 不足以收集全部用例：

```sh
python -m pip install -e ".[dev,desktop,ocr,mcp,team,postgres]"
python -m pytest -q
```

前端在 `frontend` 目录按锁文件执行 `npm ci --ignore-scripts --no-audit --no-fund`，再运行 `npm test` 和 `npm run typecheck`。安装依赖会访问包仓库，但不是模型/搜索验收。不要在当前产品实例的数据目录内运行这些命令。

本地回归必须使用合成数据，不继承真实服务凭据或生产数据库/解析器地址。官方 DSH、PostgreSQL、Docker 等可选集成测试需独立环境和显式测试变量；报告跳过原因，不把默认跳过算通过。打包与真实供应商验收另走固定候选流程。

发布回归优先使用 `scripts/run_offline_tests.py --output <源码外全新目录>`，它会隔离数据并清除继承的提供商配置。双平台作业、官方 DSH 合成协议与独立 wheel 安装的范围及局限见 [CI 说明](release-ci.md)。不能把测试脚本的联网保护当成执行任意不可信代码的安全沙箱。
