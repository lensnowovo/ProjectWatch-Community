同日最新调整：维护者要求先收尾 Windows，Mac 验收暂缓。本阶段只准备 Windows 的发布 Go/No-Go；Mac 中间包不进入已验证下载清单，恢复时继续原实机门槛。正式发布范围仍以最后明确确认的资产清单为准。

## 系统与运行时

- Windows 的最低系统版本必须由最终内置运行时约束及实机结果共同决定，不能只凭安装器能打开承诺。
- 已在 Windows 11 x64、系统 build 26200 做本机隔离安装态验证；独立用户实机仍待验。
  [Node 24.22.1 固定版本的支持表](https://github.com/nodejs/node/blob/v24.22.1/BUILDING.md#platform-list)
  将 Windows x64 下限列为 Windows 10 / Server 2016，并明确排除厂商已停止支持的系统版本；
  [Python 3.13 文档](https://docs.python.org/3.13/using/windows.html)的运行时下限为 Windows 8.1。
  这只是上游运行时边界，不等于整包在所有 Windows 10/Server/ARM 系统实测通过。
  当前独立验收优先 Windows 11 x64；Windows 10 具体版本须另记录系统支持状态与整包结果，
  不以安装器可打开代替确认。Windows ARM 与 Server 不在本次用户包验收承诺中。
- Mac 现有 plist 指定 macOS 13.0；此为构建声明，最终支持范围仍须匹配 Node/DSH/原生依赖和实机系统。未测试系统不标记通过。
- Windows RC2 输入固定 Python 3.13.17、Node v24.22.1；DSH 固定 0.2.1-rc.2 并更新传递依赖锁。Mac 中间包仍为原输入，暂缓，不继承 Windows 的补丁验收。以实际构建清单和代码为准，不在安装时获取“最新版”。
- 运行时和依赖改变需重新核对许可、原生架构与安装态协议，不能继承旧包通过记录。

## 版本与渠道

- 只读核查时公共仓库仅有 `v0.2.0-alpha.1`：源码 ZIP、wheel、校验清单，没有当前桌面候选资产。
- 本地源码已采用 `0.2.0rc2`（前端 `0.2.0-rc.2`），对应预备标签 `v0.2.0-rc.2`；RC1 因安全依赖修补保留为历史候选。最终稳定版本预备 `0.2.0` / `v0.2.0`。尚未创建标签，最终候选资产与哈希仍待冻结；2026-10-23 再次只读查重时公共仓库仍仅有 alpha 标签。
- 每个 RC 对应唯一源码树、依赖清单、两平台文件清单和 SHA-256。代码/打包变化形成新候选，禁止替换同名已发布文件。
- 稳定与预览更新渠道分开。安装包更新与源码 Git 更新分开，不自动覆盖本地定制。
- 最终发布以 [发布准备状态](release-readiness.md) 的 Go/No-Go 为准，维护者明确确认后才操作公开仓库；原始验收回执私下保留。
