# 真实监控验收标准

这是验收要求，不表示当前候选已经通过。使用固定安装包、独立数据目录和公开案例，
不借用用户真实项目、不改数据库制造停止或唤醒。每轮先说明模型、搜索和阅读的
预计量并取得费用授权；没有授权不启动真实服务。遇到结果不明立即停止新增调用，
不自动重试或换任务绕过，也不强行终止在途请求。

| 编号 | 必须证明 | 不算通过 |
| --- | --- | --- |
| A01 主体与档案 | 名字/材料入口确认正确主体；介绍、人员、产品/技术、竞对和行业分别有来源或明确缺口 | 只有介绍、用总条数代替覆盖 |
| A02 长期关联 | 有来源的“因为何事，所以关注谁”，后续收集可回溯到正确对象 | 新闻顺带提到就视为竞对 |
| A03 临时研究 | 有事件依据、父关联、范围和明确结束条件 | 为展示闭环硬造问题 |
| A04 综合判断 | 引用有效；报告期、单位、人物关系、计划/意向限定保留 | 把研究资料增多当作公司进展 |
| A05 修订写入 | 回执与实际范围一致；已执行/提案/未执行分开，新证据是否已纳入明确 | 仅凭模型总结宣称已保存 |
| A06 自然停止 | 正常链路按回答、无增量或边界规则停止；原因持久保存，父关联继续保留 | 测试脚本结束、杀进程或手改状态 |
| A07 重复不唤醒 | 重放旧材料不增加研究代次，不重新排队 | 用采集时间变化冒充新证据 |
| A08 新证据再收口 | 同对象、同研究范围的未消费材料只唤醒一次，再完成判断、修订和自然停止 | 无关材料触发或只验唤醒不验结束 |
| A09 失败边界 | 来源不可用、模型失败、在途和结果不明区分，已有结果保留 | 自动重试未知付费结果 |
| A10 页面一致性 | 项目、任务、循环状态一致，光轨只随真实阶段和保存变化 | 计时伪进度、隐藏缺口 |
| A11 轮次与保留 | 实际产出、具体缺口、停止原因及分支状态清楚，原数据/配置/暂停不变 | 缺回执记零或改动原实例 |

新证据样本须有来源与固定哈希，相对该分支确实未被消费；不得篡改日期。
没有符合条件的新材料就记未覆盖，不临时扩大搜索预算或捏造输入。
公开来源打不开、未披露或无法确认可以是具体缺口，关键事实错误不能以此豁免。

报告逐项写通过/失败/未覆盖，记录候选哈希、时间、实际调用与 token、缺失用量、
校验退回和内容核查结果。录像标明真实或合成、是否倍速；合成协议不能冒充真实验收。
结果与发布状态见[发布准备状态](release-readiness.md)。
