# Windows 首次使用检查表

使用新的源码目录和数据目录，配置自己的账号，不复制他人的 Key 或业务数据库。
安装参考 [开发指南](developer-quickstart.md)。版本、SHA-256 以 GitHub Release 附件为准。

记录 Windows、Python、Node 版本和包编号；每项填写“通过 / 失败 / 未测试”，失败只提供脱敏错误。

| 操作 | 应看到什么 |
|---|---|
| 核对 SHA-256、在新目录安装 | 依赖安装与 pip check 成功，没有开发机路径要求 |
| 打开设置，配置自己的模型和搜索 | Key 不明文回显；测试连接结果清晰；真实请求会使用自己的额度 |
| 输入公司名并确认 | 能完成首轮任务，看到公司信息、来源、任务状态与用量 |
| 添加获准的 BP 或合成材料 | 原件和项目关联正确，解析后内容可查看 |
| 暂停、关闭、重新启动 | 项目、材料、配置和原暂停状态保留 |
| 停机备份、恢复到另一个新目录 | 校验成功，材料与项目保留；新目录的 Agent 授权需重新连接 |
| 设置 → 更新与网络 → 检查软件更新 | 未配置正式源时明确提示，不猜测私有远端、不自动下载升级 |
| 复制 Agent 交接说明 | 能复制状态与安全要求，不含密钥或材料正文 |

源码 ZIP 不含 `.git`，因此不支持 Git 快进更新；从公开仓库 clone 的用户才能走源码升级流程。
未配置源时优先显示“尚未配置正式更新源”；配置源后非 Git 安装显示独立安装指引，不冒充已最新。
暂不需要人为修改 Git 或制造真实收费错误；本地定制、失败、备份和快进已有合成回归。
当前预览标签不进入稳定更新通道；在稳定版本发布前，更新检查会报告暂无稳定版本。

结果不明时不要反复点击或删除回执；停止重复操作并反馈。不要上传 Key、真实 BP、完整配置或原始数据库。
