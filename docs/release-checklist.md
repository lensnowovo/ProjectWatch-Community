## 冻结候选

### 本次 Windows 公开预览范围

维护者于 2026-10-24 选择公开预览版，并接受披露已知分析错误及未覆盖项。
以下稳定版完整门槛仍保留，不能因为改称预览就勾选通过。本次预览另核对：

- [ ] 精确最终候选产品、净化源码、资产、许可附件和哈希一致；没有混入未冻结补丁。
- [ ] 无已知未处理的数据/凭据安全、非授权重复计费或安装启动阻断；独立 Windows 安装反馈收到并审阅。
- [ ] 已知审批范围混写与真实停止/唤醒等未覆盖项在 README 入口和 Release 说明中可见，不仅埋在开发日志里。
- [ ] 固定候选远程离线 CI 通过；空闲观察按真实窗口审阅，不挪用其他版本证据。
- [ ] 最终第三方分发权利和附件审阅完成。预览版不豁免许可要求。
- [ ] 下载、使用说明、反馈模板和贡献入口指向同一版本；明确未签名、API 费用与 Mac 暂缓。
- [ ] 维护者确认精确发布清单；GitHub 标记 prerelease，不冒充稳定版。

预览范围只接受已明确披露的既知分析局限；新增严重故障仍须单独评估。
日期是目标，不授权绕过未完成项。公开后按下文核对真实下载和反馈入口。

## 获准后执行

### 候选 CI（不是发布）

本地已准备 `.github/workflows/release-candidate.yml`：维护者手动选择已审阅的 ref，
填入完整 40 位小写提交 SHA。工作流核对 checkout 与触发 SHA 一致，随后复用同一
提交的离线 CI（含前端、DSH 合成协议、wheel 与全新安装态烟测），只输出审阅结论。
它没有仓库写权限，不接受模型/搜索密钥，不创建 tag、Release 或部署，也不把
远程重新构建的 wheel 自动认作本地已冻结安装器。

远程首次运行前，须经维护者批准同步这些文件，并在仓库设置中配置
`release-candidate-review` 环境的 required reviewers / 分支限制。**仅在 YAML
中写环境名称不会自动创建审批规则**；规则未配置不应声称“已受保护”。是否同步、远程执行及环境保护是否配置，须核对该候选的实际回执；旧本地状态不能代表今日仓库。GitHub 的[复用工作流说明](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows)
说明相对路径调用会采用调用方同一提交，而不是另取移动中的 main。

CI 绿灯不替代固定安装器生命周期、真实 A01–A11、独立首次使用、48 小时观察、
安全许可与最终资产批准。安装器和源码附件仍按下列精确清单独立审阅后交付。

### 正式发布（另行确认）

1. 同步已审阅的净化发行树，按确认范围合并。不得附带私有回执、密钥或未经审阅的新改动。
2. 创建确认过的 tag / Release，上传固定资产与校验清单。保持预览/稳定渠道语义一致。
3. 从公开下载入口重新下载核对哈希，检查 README、说明与更新入口；不能只验证本地文件。
4. 核查公开 Issue 表单和反馈链接。失败则标记发布未完成，说明影响与修复动作。
5. 按 [维护流程](maintenance.md) 启动首周反馈跟进；没有反馈不能记为用户全部成功。

## 遇到阻碍

- P0/P1 未闭合则停止发行，不用“已知问题”绕过核心能力。
- unknown 请求不自动重试、不删除授权回执；需要再次调用时重新明确范围与预算。
- 回滚不直接覆盖活动数据库；先在新目录恢复成对备份验证，再由用户确认切换。
- 未取得正式授权的外部写入、发布和主实例修改始终保持未执行。
